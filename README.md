# Bill Hub

Личный кабинет для показаний воды, горячей воды, газа и электричества в Бишкеке. Next.js + React, SQLite, собственный вход по паролю. Один владелец / одно домохозяйство, один лицевой счёт каждого поставщика и несколько счётчиков на счёт.

## Что работает

- Лицевые счета, показания по месяцам, история, экспорт JSON и режим примера.
- Проверка чисел, сохранение ведущих нулей в лицевом счёте, сравнение с предыдущими принятыми показаниями.
- Газ: адаптер публичной формы Gazprom, предварительная проверка данных и явное подтверждение отправки. На реальном лицевом счёте ещё не проверялся.
- Вода, теплосеть и свет: сохранение, подготовка данных и переход на официальный сайт. Автоматическая отправка для них пока не подключена. Подробности: [поставщики](docs/PROVIDERS.md).
- Защита от двойной отправки. При потерянном ответе запись остаётся в статусе «результат неизвестен» и не отправляется повторно автоматически.

Показания вводятся пользователем. Проект не считывает физические счётчики и не придумывает ежемесячный расход. Период и сроки считаются в `Asia/Bishkek`.

## Быстрый запуск: обычный Docker

Нужны Git и Docker Engine / Docker Desktop. Compose не используется.

```bash
git clone https://github.com/damilurg/bill-hub.git
cd bill-hub

# Создаёт .env и один раз показывает сгенерированный пароль.
docker run --rm -it --user "$(id -u):$(id -g)" -v "$PWD:/work" -w /work node:24-bookworm-slim \
  node scripts/setup.mjs --url http://localhost:3000

docker build --pull -t bill-hub:local .
docker volume create bill-hub-data

docker run -d --name bill-hub \
  --restart unless-stopped --init \
  --env-file .env \
  --mount source=bill-hub-data,target=/data \
  -p 127.0.0.1:3000:3000 \
  --read-only --tmpfs /tmp --tmpfs /app/.next/cache:uid=1000,gid=1000 \
  --cap-drop ALL --security-opt no-new-privileges \
  --log-opt max-size=10m --log-opt max-file=3 \
  bill-hub:local
```

Откройте [http://localhost:3000](http://localhost:3000), войдите с логином `admin` и сохранённым паролем. `setup` отказывается перезаписывать существующий `.env`. Команды рассчитаны на Bash (Linux/macOS). В PowerShell уберите `--user "$(id -u):$(id -g)"`, используйте `${PWD}` для mount и замените переносы `\` на обратную кавычку.

По умолчанию отправка поставщикам выключена. После настройки собственных счетов задайте в `.env` `LIVE_SUBMISSIONS_ENABLED=true` и пересоздайте контейнер той же командой. Каждая отправка всё равно требует проверки счёта и значений в интерфейсе. В CI и тестах реальные показания не отправляются.

Для сервера укажите при setup `--url https://bills.example.com` и настройте HTTPS через Nginx: [развёртывание, обновление, бэкапы](docs/DEPLOYMENT.md). `APP_URL` должен точно совпадать с адресом в браузере.

## Разработка без Docker

Нужен Node.js 24. Для установки зависимостей используется зафиксированный `package-lock.json`.

```bash
npm ci
npm run setup
npm run dev
```

```bash
npm test
npm run typecheck
npm run build
npm run test:smoke
npm start
```

`test:smoke` сам запускает production standalone на `127.0.0.1:3123` с временной базой и тестовым паролем, проверяет HTTP API и перезапуск, затем удаляет тестовые данные. На реальный сервер этот тест направлять не нужно.
